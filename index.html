PROJECT 01 / 16

RPM CRM.

A Firebase and Firestore-backed CRM for a digital marketing call center, designed around role-based access and a lead-to-client pipeline.

ROLEFull Stack / CRM
YEAR2026
TYPEBusiness Web App
STACKReact / Node.js / Firebase / Firestore
01 — OVERVIEW

The system.

RPM CRM organizes the workflow of a digital marketing call center from first contact to converted client. The system gives each team the tools and visibility required for its part of the pipeline.

The architecture separates responsibilities while preserving the full lead history, creating a clear operational view for admins and focused workspaces for each role.

02 — ROLES

Four teams.

The challenge was to keep a multi-role operation coordinated without forcing every user into the same overloaded dashboard.

Access control and workflow clarity were treated as first-class product requirements.

  • Admin oversight and role-based access
  • Dialer workflow for outreach and lead qualification
  • Closer workflow for follow-ups and conversions
  • Support Manager visibility after conversion
  • Connected lead-to-client pipeline
03 — WORKFLOW

Lead to client.

A lead enters through the dialer process, is qualified and passed to a closer for follow-up and deal progression. Once converted, the support team can continue the relationship with the same context intact.

01 — Dialer

Outreach, qualification and lead capture.

02 — Closer

Follow-ups, deals and conversion tracking.

03 — Support

Post-sale communication and continuity.

04 — TECHNOLOGY

Implementation.

  • React dashboard interface and reusable workflow components
  • Node.js business logic and API-ready service layer
  • Firebase Authentication for access control
  • Firestore for real-time lead and client data
  • Role-based application structure
  • Lead status and pipeline management
  • Responsive dashboard interface
  • Interactive data management workflows
05 — DEVELOPMENT

How it was built.

The first stage was mapping how information moves between teams. Screens and permissions were then shaped around those real operational handoffs.

Reusable patterns keep lead records, status changes, team views and client details consistent across the application.

The result is a practical CRM foundation for tracking deals end-to-end while keeping each role focused on its next action.

06 — MY ROLE

What I handled.

  • CRM information architecture
  • Role-based workflow design
  • Responsive frontend development
  • Firebase and Firestore integration
  • Lead pipeline and client record flows
  • Interface refinement and usability
PROJECT 02 / 16

SENSORY BREW.

An Android coffee shop application built with Java, Firebase and MVVM, with mood-aware discovery, cart management and Google sign-in.

ROLEAndroid / Java
YEAR2026
TYPEMobile Application
STACKJava / Kotlin / Firebase / MVVM
01 — OVERVIEW

The experience.

Sensory Brew is a coffee shop app that makes discovery, selection and ordering feel personal. It combines a focused mobile interface with Firebase-backed account and app data.

The app was organized into five modules: Splash, Login, Dashboard, Cart and Shared. This keeps authentication, browsing and order state understandable as the product grows.

02 — MODULES

Five focused modules.

Splash / Login

Entry flow, authentication and Google sign-in.

Dashboard

Mood-based and GPS-aware menu discovery.

Cart / Shared

Persistent basket state and shared managers.

03 — ARCHITECTURE

Built for reuse.

  • Java and Kotlin Android development
  • Firebase-backed authentication and data
  • MVVM separation of UI and application logic
  • LiveData-driven home screen updates
  • CartManager for basket state
  • FavoritesManager and LoyaltyManager singletons
04 — INTERACTION

Personalized discovery.

Users can discover menu items through GPS-based context and mood-based filtering, making the dashboard feel more relevant than a static product list.

Shared managers keep cart, favorites and loyalty behavior consistent across screens while LiveData keeps the home screen responsive to changing data.
