PROJECT 01 / 04

VAULT.

A premium crypto portfolio management experience designed to make complex financial data feel simple, structured and easy to understand.

ROLEFull Stack / UI
YEAR2026
TYPEWeb Application
STACKHTML / CSS / JS / Firebase
01 — OVERVIEW

What is Vault?

Vault is a crypto portfolio dashboard concept created to bring holdings, portfolio performance, transactions, watchlists and financial information into one focused interface.

The goal was not to make another complicated trading dashboard. The interface was designed around hierarchy: the most important information should be immediately visible, while deeper information remains accessible when needed.

02 — PROBLEM

The challenge.

Crypto dashboards can quickly become visually overloaded. Prices, percentages, assets, transactions and charts compete for attention.

The challenge was to create an interface that could contain a lot of information without feeling like a spreadsheet.

  • Clear portfolio hierarchy
  • Readable financial information
  • Fast access to holdings
  • Responsive behaviour across screen sizes
  • Consistent visual language
03 — HOW IT WORKS

System flow.

The interface is structured around a central portfolio overview. From there the user can move into holdings, transactions, watchlist and individual asset information.

01 — Dashboard

Portfolio overview and key metrics.

02 — Holdings

Assets, balances and allocation.

03 — Transactions

History and activity tracking.

04 — TECHNOLOGY

What was used?

  • HTML5 for semantic structure
  • CSS3 for responsive layouts and visual system
  • JavaScript for interaction and application logic
  • Firebase for backend services and data
  • Firestore for structured application data
  • Responsive CSS for mobile and tablet layouts
05 — DEVELOPMENT

How it was built.

The first stage was defining the information hierarchy. Before adding visual effects, the dashboard structure was kept intentionally simple.

The interface was then translated into reusable layout patterns: cards, tables, navigation states, data sections and responsive components.

After the main functionality was established, motion and micro-interactions were introduced carefully so they would support the interface instead of becoming distractions.

06 — MY ROLE

What I handled.

  • Interface structure
  • Responsive frontend development
  • Dashboard interaction design
  • Component styling
  • Application logic
  • Database integration concepts
  • Visual refinement and micro-interactions
PROJECT 02 / 04

CRM.

A business-focused CRM experience designed around three core teams: lead generation, sales closing and customer support.

ROLEFull Stack / UX
YEAR2026
TYPEBusiness Web App
STACKJS / Firebase
01 — OVERVIEW

The system.

The CRM is structured around the actual workflow of a digital marketing sales operation rather than trying to place every team into one generic dashboard.

The system separates lead generation, sales and support while keeping the client journey connected between teams.

02 — WORKFLOW

Three teams.

Lead Generation

Cold calling, lead qualification and appointment setting.

Sales Closers

Follow-ups, deals and conversion workflow.

Support

Customer communication and post-sale support.

03 — TECHNOLOGY

Stack.

  • HTML / CSS / JavaScript
  • Firebase Authentication
  • Firestore database
  • Role-based application structure
  • Responsive dashboard interface
  • Interactive data management
04 — DEVELOPMENT

Building the workflow.

The application was designed around the movement of a lead. A record can begin with lead generation, move into the sales process and eventually reach support.

The important part was maintaining context between these stages without making the user repeatedly enter the same information.
